# Img2UltraHDR 0.1 本机验收记录

日期：2026-09-30。验收环境为 Apple Silicon MacBookPro18,1、16 GB 内存、macOS 26.7.1。最低部署版本设为 macOS 15；尚未在 macOS 15 或其他 Mac 上实测。

交付位置：`~/Applications/Img2UltraHDR.app`；可重复构建产物：`dist/Img2UltraHDR.app`。使用方法、依赖与数据位置见 [应用说明](macos-app.md)。

## 当前结论

单张 CR2 / RAF 的原生编辑和导出流程已实现，并在 Finder 启动的应用中走通。默认配方保持 Clear V8 R5 / Natural V8。同一浮点输入的冻结版本对照、交互参数、取消、恢复和编解码检查通过。

**尚不能把 M5 标为全部通过**：1536 像素预览的性能尚未达到 3 / 5 秒目标；真实 HDR 屏幕观感、外接显示器切换及长期使用仍需人工验收。完整 RAW 回归结果在下方记录，不能用自动检查替代视觉结论。

一次 CR2 实测暴露出 Darwin 偶尔保留只有僵尸进程的进程组，导致 `killpg` 返回 EPERM。现已只对“确认没有活进程”的组忽略该错误；对于真实无法终止的活进程不掩盖错误。失败记录保留在 `ui-final-cr2/`，修复后的记录位于 `ui-cr2-retry/`。

## 冻结配方与画质

冻结代码基线为提交 `013d232`；运行前的代码副本保留在 `baseline/hdrimg/`。没有修改风格参数文件、历史照片或冻结参考输出。

- **38 / 38**：19 份固定浮点输入 × Clear / Natural，SDR JPEG 和 HDR 半浮点编码输入均逐字节一致。证据：`equivalence-policy/equivalence.json`。
- **12 / 12**：六张 RAW 的 1536 像素底稿 × 两种风格，在曝光、高光、阴影、饱和度及 HDR 强度调整下，串行和并行的 SDR / HDR 输出逐字节一致。证据：`parallel-six/parallel-equivalence.json`。此检查验证并行实现，不把 Clear 显影底稿重新标作 Natural 专属显影。
- 独立阴影覆盖黑色、中灰、±2 EV、单调性、颜色比例和有限数值；SDR 亮度不会改变 HDR 像素；手动相对调整不改变自动保护策略。证据：`tests/test_editor.py`。
- CR2 / RAF 分别检查自动、相机、自定义白平衡，固定测光参考复用，相对曝光不重新显影，并检查 Natural 预览。证据：`white-balance/white-balance.json`。

### 37 张 RAW 完整回归

**37 / 37 通过**：30 张 CR2、7 张 RAF。每张均从 RAW 准备底稿，生成预览、全尺寸 SDR / Ultra HDR、保留元数据并通过 HDR / SDR 解码检查。

| 预览与全尺寸对照 | 每张误差中位数的最大值 | 每张误差 95 分位的最大值 |
| --- | --- | --- |
| SDR | 0.01455 EV | 0.06034 EV |
| HDR | 0.01644 EV | 0.04130 EV |
| 计划阈值 | 0.05 EV | 0.2 EV |

全部样片的上述分位数均通过。单张照片中超过 0.2 EV 的 HDR 有效像素占比最高约 0.44%，差异图单独保留供局部检查。汇总见 `acceptance-summary.json`。

大规模回归在最后一次数值等价并行优化前启动；最终实现另以六张固定底稿 × 两种风格逐像素对照串行输出，不把不同阶段的引擎标识混称为同一次运行。

结果文件：`raw37/raw-suite.json`。HDR 预览与缩小全尺寸的对照：`raw37/hdr-preview-comparison.json`；逐张差异图为 `raw37/*_hdr_difference.png`。有效亮度区定义为两张线性亮度均大于 0.02；分别统计每张照片的绝对亮度 EV 误差。

历史成品的重新显影对照单独保留在 `raw37/repeat-raw-comparison.json`。 其中 20 / 37 张缩至 1536 后的 SDR 像素全部相同；所有照片重新显影对照的最差亮度误差中位数为 0.00901 EV，最差 95 分位为 0.03475 EV。此处不代表全尺寸文件字节一致。这与“同一浮点底稿的算法等价”是不同检查：RawTherapee 自动白平衡会受显影线程设置影响，旧基准文档已经记录此限制。9453 的色温偏置在本次和历史显影之间不同，不能宣称所有历史 RAW 成品逐像素重现。参见 [原 R5 验收说明](phone-clear-v8-r5.md)。

原尺寸 SDR 抽查在七张代表照片上保存了 14 组裁切对照（`native-crop-review/`），检查发丝、衣物、皮肤和暗背景。已查看的局部没有发现新增明显黑白轮廓；9453 可见重新显影造成的暖色差异，9486 的原有色彩风险没有被顺带修饰。HDR 差异图仍存在少量超过 0.2 EV 的局部，不能用总体分位数保证每个边缘像素一致；最终细节判断应使用 100% 全尺寸检查和实屏观看。

原片及历史证据的 4,042 条文件记录经过哈希核对，未发现修改或丢失；记录之间可能重叠，不能解读为 4,042 个不同文件。证据：`preservation.json`。

## 性能、取消与内存

六张固定样片为 `0N6A9034`、`0N6A9169`、`0N6A9406`、`0N6A9416`、`0N6A9453`、`DSCF8111`；覆盖宽幅、竖幅、人物、室内/室外、强高光、暗部及天空内容。每张测量 3 次新的参数渲染，共 18 次，保持 1536 像素、完整照片分析和所有质量保护。

| 操作 | 实测 | 判定 |
| --- | --- | --- |
| 缓存底稿的预览渲染与编码 | 中位数 **4.27 秒**，95 分位 **5.42 秒** | 尚未达到 ≤3 / ≤5 秒 |
| 真实显影阶段取消 | 0.012 秒 | 通过；任务组及临时缓存已清理 |
| 全尺寸渲染阶段取消 | 0.031 秒 | 通过 |
| 编码阶段取消 | 0.018 秒 | 通过 |
| 已解码 HDR / SDR 图像缓存切换 | 缓存读取最大 0.313 ms；冷全尺寸 HDR 解码约 287 ms | 仅为加载器测量，未宣称端到端 UI 切换已达 200 ms |

另有并行验证期间的调用热点记录 `final-preview-profile.txt`，可用于定位人物分析、色域压缩及边缘扫描的成本；它受同时运行的 RAW 任务影响，不作为性能基准。

预览测量排除首次 RAW 准备、白平衡重显影和控制器启动。使用独立的不可变底稿缓存，并在每次测量期间短暂暂停本任务的其他验证进程，随后恢复；证据：`benchmark-isolated/benchmark.json`。最初共用测试缓存的试跑因缓存淘汰而终止，`benchmark/` 中的未完成结果不计入结论。

优化保留相同数值结果：预编译 Vision helper、浮点场景/人物分析缓存、按真实输入标识复用边缘蒙版、精确 C 扫描/颜色计算，以及最多 3 个预览行块并行。全尺寸主图仍使用分块串行处理。没有通过关闭人物/肤色处理、缩小预览或改变配方来达标。

本次全尺寸渲染、编码和验证为 **34.6–164.9 秒，中位数 61.4 秒**；包含 RAW 准备的整张流程为 **81.4–263.9 秒，中位数 134.4 秒**。监测到的进程树 RSS 峰值为 **4,815 MiB（约 4.70 GiB）**；监测从第六张附近开始，不能覆盖更早时段。

全尺寸耗时和进程树内存记录分别见 `raw37/raw-suite.json`、`raw37-memory.json`。批量验收期间运行过其他检查，且有少量为预览基准而暂停的时段；这些逐张总耗时不作为独占机器的性能基准。RSS 是父进程与活跃子进程的驻留内存之和，不是整个系统内存，也不是长期泄漏证明。

## 已覆盖的异常与待验收项目

自动检查覆盖了非法参数、损坏 RAW、原片移动/改变、过期响应、连续取消、控制器死亡后的子进程清理、导出重名、保存中途错误的双文件回滚、失败不发布完整缓存标记、缓存淘汰保护和引擎版本失效。取消明细在 `cancellation-final/cancellation.json`。

以下项目保留为待验收，不能标为通过：

1. 人在本机 HDR 屏幕上确认高光亮度、肤色和人物边缘，并和外部查看流程对照。普通窗口截图无法提供这个结论。
2. 外接 SDR / HDR 显示器之间移动窗口、改变系统亮度后的实际观感。代码会更新显示状态，但尚无完整人工记录。
3. 长时间反复编辑的内存趋势，以及磁盘实际耗尽、系统目录权限变化的端到端 UI 场景。代码包含检查及错误处理，单元测试的异常注入不能替代这些实机场景。
4. 1536 像素预览达到原定 3 / 5 秒目标；后续继续以重复分析和数值热点为优化对象，不降低质量保护。

早期检查创建的浮点缓存已清理，JPEG 和 JSON 记录移至 `initial-cache-evidence/`、`white-balance/cache-evidence/`；清理范围记录在 `scratch-cleanup.json`。保留六张性能样片的不可变底稿、37 张最终成品及应用自己的日常缓存，未清理原片或历史冻结输出。

首版自用应用及共享引擎已交付；上述条目明确限定了验收结论。
