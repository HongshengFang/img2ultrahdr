# 手机样本校准记录

本文保留初始版本的校准历史。当前 `phone-natural` 已更新为 [V8 自然人像方案](phone-natural-v8.md)，下文旧参数不代表当前默认值。

## 样本和方法

`jpg_hdr_sample_effect/` 的 12 组 Pixel 9 DNG／Ultra HDR JPEG 以同一文件名前缀配对，全部带有效的 Display P3 ICC 和 HDR gain map。样本跨室内外、日夜、白色衣物人像、蓝天绿植、明亮白色物体和室外明暗反差。原始照片已加入 `.gitignore`，本记录只保存统计和处理方法。

分析脚本 `scripts/analyze_phone_pairs.py` 用 RawTherapee 将 DNG 临时显影到线性 Rec.2020。JPEG 按 EXIF 方向旋正；DNG 由 RawTherapee 输出正向画面；两者按共同的 4:3 中心画幅裁切，并舍弃边缘 2.5%，降低手机与 RAW 的裁切差异。10 组显影图与 JPEG 的宽高各差 8 像素，另 2 组差 72 × 56 像素。然后分别统计线性 RAW、P3 SDR 基础图和解码后的线性 HDR。两种相机处理链可能有几何校正和多帧合成差异，因此这里比较画面分布，未把坐标相同的像素当作严格匹配的色块。

复现统计：

```bash
python scripts/analyze_phone_pairs.py jpg_hdr_sample_effect \
  --output outputs/phone_sample_analysis.json --audit-style
```

## 观察到的规律

- 手机 JPEG 的 SDR 画面中位亮度随场景变化很大，在线性 SDR 白为 1 的尺度下为 **0.011–0.409**；不是对所有照片固定增加曝光。12 组的 SDR 99.5 百分位为 **0.501–0.903**，接近 SDR 白的像素最多只占 **0.37%**。明亮感与保留白色纹理可以同时存在。
- 解码后的 HDR 峰值为 **1.60–6.00 倍 SDR 白**，超过 SDR 白的像素占 **0.38%–54.63%**，由场景决定。亮部应在 HDR 中扩展，不能靠把 SDR 整体推到白色来模拟。
- SDR 中有 **0.12%–9.57%** 的取样像素落在 sRGB 色域之外，P3 在一些场景确实有用；P3 只扩大可显示颜色范围，并不改变曝光或局部对比。
- 以 OKLab 中间调色度与明度之比衡量，手机 JPEG 与 DNG 显影图的比值在 12 组之间约为 **0.60–1.73**。这不是一个固定饱和度倍率：暗光与部分暖色场景甚至会降低色度。因此模式采用温和的选择性鲜艳度，同时限制肤色增强。

这些数值用于确定处理方向和边界，不作为两种不同相机照片之间的绝对色彩目标。DNG 只参与参考分析；正式 `render` 输入仍为 CR2／RAF。

`--audit-style` 还会把每组 DNG 临时缩为预览图，经同一渲染函数生成新模式的 SDR 与线性 HDR，用来发现跨场景的亮部问题。首次检查发现三组极暗场景的 SDR 有约 9%–10% 像素接近白色，因此为新模式的 SDR 亮部增加了随场景跨度变化的渐进压缩。复查后，12 组预览中有 11 组近白像素比例不超过 **0.01%**，一组夜景约 **0.70%**。夜景的整体亮度和色彩仍可能偏离手机的多帧计算结果；这项预览检查不能替代跨相机、同屏幕的视觉校准。

## 实现与验收

`--style phone-natural` 的预设值：中间调 +0.30 EV、SDR 亮部压缩 0.35、局部对比 0.12、选择性鲜艳度 0.15、Display P3 SDR 输出。亮度映射保持单调；局部对比按低分辨率边缘感知亮度底图计算；P3 像素由线性 Rec.2020 转换并压入 P3 色域，JPEG 嵌入 Display P3 ICC，EXIF 主色域标为 Uncalibrated。Ultra HDR 编码器同时收到 P3 SDR 和 Rec.2020 HDR 的正确色域参数。

使用 `0N6A9479.CR2` 固定 +1.0 EV、5500 K、tint 1.0、对比度 1.35、饱和度 1.18 对比：当时的 `natural` 风格重新生成的 SDR 与旧成片逐像素一致；`phone-natural` 的 SDR 面部、浅色衣服和墙面仍保有层次，绿植与发色更分明。Ultra HDR 解码峰值由 **3.316** 增至 **3.392** 倍 SDR 白，超过 SDR 白的像素比例由 **12.17%** 增至 **22.57%**。这些是编码与数值检查；最终观感仍应在同一 HDR 屏幕与亮度设置下看原图，而不是以聊天预览判断 HDR。

在腿部矩形区域，SDR 线性亮度中位数从 **0.416** 升至 **0.477**，HDR 第 95 百分位从 **0.708** 升至 **0.857**。该区域尚未出现超过 SDR 白的像素；当前模式保持自然明快观感，不能将这张照片的腿部保证为 HDR 高光。对照页保存在忽略提交的 `outputs/0N6A9479_phone_natural_100/compare.html`，可在同一浏览器中切换 SDR 与 Ultra HDR 并排查看。

## 更接近手机直出的选用风格

在固定 `0N6A9479.CR2` 的曝光、白平衡、对比度和饱和度后，对比了四档逐渐增强的中间调、亮部压缩、局部对比和选择性鲜艳度。最强一档让肤色与绿植显得偏用力，因此选择中间的 `phone-clear` 作为更明快的预设，并将其设为默认风格；原 `phone-natural` 不变。`phone-clear` 使用 **0.38 EV / 0.42 / 0.22 / 0.23 / Display P3**，按顺序对应这四项控制及 SDR 色域。

用全部 12 组 DNG 缩小预览重新渲染，与 `phone-natural` 相比，`phone-clear` 的画面中位亮度中位提升约 **4.9%**，中间调相对色度中位提升约 **3.6%**。11 组的近白像素比例不超过 **0.001%**；一组夜景约 **0.61%**，略低于旧预设的 **0.70%**。这项选择针对用户提供的人像和“更亮、更通透、颜色更正”的偏好；夜景的手机多帧处理仍无法由一个固定预设完全重现。

全尺寸 `0N6A9479.CR2` 使用同一组固定拍摄参数重出后，SDR 中位亮度从 **0.584** 到 **0.604**，99.5 百分位从 **0.882** 到 **0.866**，且没有近白像素；HDR 解码峰值为 **3.473** 倍 SDR 白，约 **29.28%** 的像素超过 SDR 白。SDR 和 Ultra HDR 都含正确的 Display P3 配置，gain map 已解码验证。新旧手机风格的并排切换页在忽略提交的 `outputs/0N6A9479_phone_clear_100/compare.html`。

后续对 12 组样本做了更完整的逐像素 HDR 增益及并排视觉复核；接近 SDR 白的像素比例并不足以代表手机观感。见 [12 组样本复核](phone-sample-reanalysis.md)。
